# 跨数据源人物关系图：数据构建与泛化验证方法

状态：工作方法，2026-09-26 起用于 Freebase Easy 及后续外部数据集的逐步审计。每个数据源都应保存自己的统计和决策记录；本文件只规定共同方法，不预设 Freebase Easy 一定适合训练。

## 1. 研究问题与证据边界

本项目要检验：在更换资料来源、人物收录机制和关系编码方式后，**人物社会关系对职业预测的贡献及其时期变化**是否仍能观察到。分别在不同数据集上重复同一协议，属于“跨来源复现”；在一个数据集训练、到另一个数据集测试，才属于“跨来源迁移”。两者应分别报告，不能混称为泛化。

原论文研究的是职业联系和亲子职业继承，提出 OCI 与 OII；本项目的 R-GCN、R-GAT、GraphMask 等回答的是预测与模型依赖问题。OCI/OII 可以作为描述性对照，不等同于分类准确率、删边效应或因果效应。论文的“历史社会精英”也不是一般人口的代表样本。

## 2. 从 WikiElites 论文中提取的数据方法

来源：Sirui Lai、Liang Wang、Dingqi Yang，*Occupational Inheritance and Kinship: An Empirical Study of Historical Social Elites on Wikidata*，所附 PDF，重点是第 III 节（第 2–4 页）、第 V 节 B（第 6 页）及第 VII 节（第 9–10 页）。下表中的数量和处理方式是**论文的做法**，不是 Freebase Easy 的现状。

| 环节 | 论文的具体做法 | 可复用的经验 |
| --- | --- | --- |
| 人物起点 | 以跨 Wikipedia/Wikidata 核验的约 229 万名知名人物库为候选，再从 Wikidata 抽取这些实体间的关系 | 先说明“谁有机会进入样本”，再讨论最终图规模；来源的收录机制是结论的一部分 |
| 社会关系 | 起初抓到 100 多种关系；排除不属于人物社会关系或缺乏研究意义的谓词，人工核查后保留 40 种；只保留有选中关系的人物 | 先做谓词盘点和语义复核，再冻结白名单；“named after”是反例。论文提到它出现不足 122 次，**122 不是通用删选阈值** |
| 标签 | 使用三级职业本体；论文的分析排除了职业为 `miscellaneous`、`other` 或缺失的人物 | 职业映射必须能解释、能审计；低质量标签不能被硬塞进有效类别。本项目训练图可保留无标签人物作邻居，但只让有可靠标签者进入监督与指标 |
| 时间与地域 | 提取出生、死亡日期；时间分析排除缺出生日期者；对 1900 年后出生且无死亡日期者按仍在世处理；历史国名映射为现代国家展示 | 缺失值、存活假设、国名映射都要显式记录，并检查它们怎样改变不同时期的样本 |
| 时期比较 | 使用古代（500 年以前）、后古典（501–1500）、早期现代（1501–1750）、中期现代（1751–1900）、当代（1901 年起）五段；分别看关系与职业构成 | 不能只画最终指标；先报告每期人数、边数、关系组成、标签组成及缺失率 |
| 不均衡样本 | 亲子关系 OII 的逐年曲线按固定 100 或 1000 对亲子关系有放回抽样，重复 500 次并给出 95% 区间 | 历史记录密度差异很大。跨时期比较需要匹配样本规模、重复抽样和不确定性区间；还要检查较小样本是否改变趋势 |
| 结论限制 | 明确承认名人选择、欧洲语言版本、早期记录稀疏和地区稀疏带来的偏差 | “换了一个知识图谱”不足以证明普遍性；必须报告来源重合与覆盖偏差 |

论文最终报告 334,099 名人、691,503 条经筛选的原始关系记录；图 1 把其中 478,467 条归为亲属、213,036 条归为非亲属。它们是**原始关系记录数**，不能与本项目预处理后加入反向边得到的消息边数混用。论文图 2 的四个一级职业组与十个二级组是其本体选择，也不能自动视为所有数据源的原生标签。

## 3. 我们的共同数据协议

### 3.1 先建来源档案，再看模型结果

每个来源先保存：公开下载页、原始下载地址、版本或发布日期、下载日期、文件字节数、文件清单、许可证、处理脚本版本、原始记录数和已知抽取规则。默认用文件大小与压缩格式自检即可；不把校验哈希设为日常步骤。名称中含 `latest` 的发布包尤其要记录获取日期和当时的文件大小。

先写清三个总体：原始库中的实体/事实、可识别的人物、最终具有可用社会关系和职业标签的人物。所有覆盖率必须写明分母；不能把“全库实体数”写成“人物数”。

### 3.2 漏斗式审计，不从最终 CSV 倒推质量

每一步同时记录输入数、保留数、排除数和排除原因：

1. **记录与模式**：检查压缩包成员、编码、分隔格式，抽样实际行；统计谓词频次、对象类型与明显异常。优先流式读取，不为了探索先解开整个库。
2. **人物识别**：找到来源自身的 Person 类型、ID、别名与外部链接；检查同名异人、同人多 ID、类型误标。多来源链接要保留原始 ID 与规范化 ID 的对应表。
3. **关系候选**：逐个列出可能的人物关系谓词，确认两端确为人物，区分亲属、教育/指导、职业/任职、伴侣及其他；记录方向、逆关系、时间限定和中介节点。
4. **职业候选**：统计原始职业值、独立人物数、多职业比例、缺失率；建立原始值到冻结目标本体的可审计映射，保留未映射值及频次。不要通过待解释的社会关系推断标签。
5. **时间与地区**：分别统计出生、死亡、关系发生时间及地区字段的可用率；按时期和关系类型交叉统计。仅有人物生年，不能把一条社会边说成发生在该年。
6. **最终图**：只把人物作为节点。职业、学校、机构、职位和中介事件可供抽取属性或构造边，但不能悄悄混为人物节点。报告原始事实、唯一人物关系、去重后边、加反向边后的消息边，避免双计数。

每个数据源都应输出从原始记录到最终可监督人物的漏斗表，且保留被排除样本的计数。关系频次阈值、职业最低类别数和时期边界应在查看模型结果前确定，并做合理的敏感性检查；不能照搬论文中的 40 种关系或其他数据集的固定阈值。

### 3.3 映射规则必须冻结，且允许“不知道”

- 保存原始谓词、原始职业、规范化结果和人工复核依据；关系白名单及 `inherited`/`acquired` 分组应有版本。伴侣、导师、同事等语义不能仅凭字符串相似度归类。
- 对多职业人物明确选择单标签、层级多标签或其他任务形式，并在数据集之间固定比较口径。低置信度、`other`、无法映射和缺失值单列，不以相邻人物标签填补。
- 原始关系方向与程序所加 `__rev` 方向分别保存。重复事实、自环、同一关系的正反向原始记录、不同来源的重复陈述分别统计。
- Freebase/DBpedia/Wikidata 间若存在同一人物或同一外部页面，报告重合率；跨来源复现与严格独立人物测试分别做，不把 ID 不同当成人物独立。

### 3.4 为预测任务单独控制泄漏

论文为描述性分析排除无职业者；本项目默认允许无标签人物留在图中作邻居，但其 `y=-1`，不参与损失和指标。训练、验证、测试人物的标签划分与特征可见性沿用项目协议：验证/测试人物的职业不可作为邻居特征，当前 seed 人物的职业也必须 mask。职业类型边、职业推导出来的关系、同一事实的别名形式都不能作为预测职业的消息边。

报告至少包括：无边或 MLP 对照、不同关系组删边及等规模随机删边对照、多个随机种子、标签频率和节点度数分层结果。比较数据集时先保持模型、目标类别、输入特征和评估口径一致，再讨论差异。若统一不了目标本体，应明确改为“各数据集内复现”，不报告伪造的跨库准确率比较。

### 3.5 历史比较的独立性检查

明确选择以下哪一个问题，不在一张表中混报：

- **统一图、按人物出生时期分组评估**：检验一个模型对不同年代人物的依赖；图中的邻居可能来自其他时期。
- **每期单独构图与训练**：检验每个时期自身的关系结构；须说明无时间戳的边怎样归期。
- **真正的跨来源迁移**：在来源 A 训练、来源 B 测试；须先解决人物重合、标签本体与特征可比性。

所有趋势图同时给出每期有效人物、带标签人物、关系实例、不同关系类型数、职业类别数、缺失率及置信区间。固定样本量重抽样只处理抽样方差，**不能消除名人收录或来源选择偏差**。解释应限定为“在该来源和筛选协议下观察到的预测关联”。

## 4. Freebase Easy：先做覆盖审计，再决定是否建图

官方 `freebase-easy-latest.zip` 是一个包含 `facts.txt`、`scores.txt`、`freebase-links.txt` 的整体包；官方页面称 `facts.txt` 约 3.62 亿条事实、解压后约 22 GB，`scores.txt` 涵盖约 5940 万实体。**5940 万不是人物数。** Freebase Easy 做了类型扩展和部分中介关系扁平化，便于初探，但婚姻、任职、教育等事件的原始起止时间可能无法从简化事实恢复。若时间信息不足，不能用推断的“关系发生年”建立严格时期图。

**主线是全类型人物社会关系，而非仅亲属关系。** 本项目的 `Q_R_Q_extended.txt` 含 40 种原始关系，亲属之外还有导师/学生、职业合作、影响与接任、宗教授职等。Freebase Easy 的谓词名称和本体未必一一对应；应先全面盘点全部谓词中两端匹配人物的事实及样例，再人工确定“有意义的人物—人物关系”白名单及与现有 40 种关系的语义对照。`scripts/freebase_easy_relation_inventory.py` 服务于这一全面盘点；第三、四阶段的亲属结构与年龄审计只是候选关系的局部质量检查，不能替代白名单发现。

最终报告清晰的筛选漏斗：① `is-a Person` 候选；② 至少参与一条经语义核查的人物关系的节点；③ 其中有可映射职业标签的监督候选；④ 其中还有可解析出生或死亡年份的时期分析子集。无职业人物是否保留为无标签邻居，按本项目防标签泄漏的图构建协议单独决定；不要把“无生卒年”当作在所有分析中必须删除的理由。先统计各层交集，再冻结筛选规则。

第一轮脚本只读 ZIP 或解压后的 `facts.txt`，走 CPU，不启动训练，也不占用服务器 GPU。建议分成两次流式扫描：

1. **模式盘点**：读少量原始行确认格式；统计谓词及对象样式、Person 类型判定方式，列出职业、出生/死亡和人物关系候选谓词。特别检查 `people/person/profession` 与扩展的 `is-a` 事实有无重复含义。
2. **覆盖联结**：建立经核查的人物 ID 集；对候选谓词分别统计唯一主体、唯一客体、两端都是人物的边、人物中有职业/生年的比例，以及这些条件的交集。按原始谓词和拟定关系组分别报数。
3. **人工复核样本**：每个候选关系抽取若干原始三元组，核对是否真是人物间社会关系、方向是否正确、是否经过中介扁平化、同名或类型歧义是否影响判定。
4. **作出门槛判断**：先看是否存在可比的多个关系家族、足够的可靠职业标签与跨时期人物。若只剩少量职业或亲属关系，不应因为全库巨大就进入 GPU 训练；若覆盖可行，再冻结映射和划分方案。

第一轮应交付以下小文件，便于远程传回审阅：`source_manifest.json`、`predicate_counts.csv`、`person_coverage.json`、`candidate_person_relations.csv`、`occupation_values.csv`、`period_coverage.csv`、`manual_review_samples.tsv` 和一页 `decision.md`。这些文件应标明是否为全量统计或抽样估计，不能把样本比例直接当作全库人数。

### 2026-09-26：Freebase Easy 全量模式盘点

服务器上的 `freebase-easy-latest/facts.txt` 经 `scripts/freebase_easy_stage1.py --full` 扫描：362,243,831 行、23,434,234,666 字节，全部可按当前制表符规则解析；观察到 1,919 种谓词、47,409 种 `is-a` 对象。`is-a Person` 出现 3,970,878 次，去重后为 **3,970,877 个候选实体名**。这只是类型初筛；尚未核实人物身份、职业标签、人物间边和时间覆盖，不能直接作为训练样本数。文件开头 10 万行的 `Person` 只有 7 个，且样例集中在名称以 `!` 开头的实体，说明文件头抽样不能外推到全库。

`Deceased Person`、`Military Person` 等类型的计数不能直接加到 `Person` 数上：同一实体可有多个类型，是否重叠尚未审计。下一步先检查全量谓词与类型排名及原始三元组，再定覆盖联结规则。

### 2026-09-27：关系候选与数据质量信号

全量谓词频次中，`Profession` 为 3,090,256 条，`Date of birth` 为 1,924,970 条，`Children` 为 382,502 条，`Sibling` 为 314,446 条，`Spouse (or domestic partner)` 为 303,040 条；`Parent` 仅 8,808 条。这些是**全库谓词事实数**，尚未证明主客体属于候选人物，也不能直接作为关系图边数或职业覆盖人数。`Occupation` 另有 9,238 条，应与 `Profession` 分开审计。第二阶段脚本 `scripts/freebase_easy_stage2_coverage.py` 以第一阶段候选人物集核查谓词两端、独立人物覆盖及职业、出生日期、人物间亲属关系的交集，并输出固定随机种子的人工复核样例。

前 20 个候选名称中出现了网页代码样式的异常字符串，说明 `is-a Person` 列表含噪声。原始名称和三元组一律当作不可信数据，不在网页中作为 HTML 渲染；建图前还需核对 `freebase-links.txt` 中的原始 Freebase 标识、重复实体与虚构人物交叉类型。

### 2026-09-27：第二阶段全量覆盖初报

`scripts/freebase_easy_stage2_coverage.py` 扫完全部 362,243,831 行、23,434,234,666 字节，无格式错误；13 个目标谓词合计 11,156,107 条事实。3,970,877 个 `Person` 候选中，1,237,189 人有 `Profession` 事实，1,915,181 人有出生日期事实，629,004 人出现在两端均为候选人物的亲属关系事实中；职业与此类亲属关系交集为 220,999 人，再要求出生日期为 168,805 人。`Profession` 的人物主体对应 3,899 种不同原始值。扫描耗时 486.04 秒。

这些数仍是**按当前规则未经清洗的候选覆盖**：尚未检查逐谓词方向与语义、重复边、职业值质量、日期可解析率、虚构人物和噪声名称。只有查看 `predicate_coverage.tsv`、`occupation_values.tsv` 与 `relation_samples.json` 后，才能决定清洗规则和是否建图。

### 2026-09-27：逐谓词与关系样例复核

第二阶段逐谓词结果表明：`Children` 的 382,502 条事实中有 381,997 条两端都在 `Person` 候选集；`Sibling` 为 307,322 / 314,446；`Spouse (or domestic partner)` 为 302,788 / 303,040。样例中的 `Children` 通常表现为“主体是父母、客体是子女”，`Sibling` 多为看似合理的兄弟姐妹；这些仍需用重复、反向边、时间和身份检查确认。`Profession` 在人物主体上有 3,084,516 条事实、1,237,189 个不同人物，说明一人可有多个职业值，不能直接把事实数当成标签人数。

`Married To` 只有 8 条人物对事实，样例包含虚构人物以及 Elizabeth I 与 Marilyn Monroe 这样的明显错误配对；`Parent` 只有 2 条人物对事实，样例也含虚构人物。这两个谓词暂不进入主要关系图。`Occupation` 仅涉及 29 个不同 `Person` 主体，样例中也有虚构人物，暂不并入主要职业标签。`Date of Birth` 大写变体仅涉及 10 个候选人物，其样例有动物；暂时与主要 `Date of birth` 分开。`Place of birth` 的客体仅有 18 个名称与 `Person` 候选同名，却造成 3,410 条“人物对”假象，说明纯名称交集不等于正确实体类型。

第三阶段 `scripts/freebase_easy_stage3_relations.py` 只审计五个亲属候选谓词的去重、自环和反向事实，并统计候选人物与虚构/角色相关 `is-a` 类型的交叉；该标记只用于审计，不自动删除人物。随后需用出生年份约束、Freebase 原始标识和人工抽样进一步核验边。

### 2026-09-27：第三阶段关系质量结果

五个亲属候选谓词的全量审计无格式错误。`Sibling` 的 307,322 条人物对事实恰好构成 153,661 组双向关系；`Spouse (or domestic partner)` 的 302,788 条也恰好构成 151,394 组双向关系，且这两类均无自环或重复的同向事实。两类在建图时应各保留一条无向边，不能把两方向当成独立证据。`Children` 有 381,997 条不同的有向人物对，其中 102 条自环、42 组相互指认子女的双向对；这些应隔离复核，不直接进入父母→子女边。排除自环和双向冲突的两个方向后，还有 381,811 条结构上未发现这两类异常的有向候选边，**尚不代表语义正确**。

宽泛的“虚构相关类型”匹配标记了 7,300 名 `Person` 候选，但其中包括 `Fictional Character Creator`、`Character Actor`、`Science-fiction writer` 等真实人物职业或角色，因此不能据此直接删除人物或边。异常样例中 A. A. Milne—Christopher Robin Milne、Aaron Spelling—Tori Spelling 等真实亲属也被此宽泛规则标记。`Person Or Being In Fiction` 同样可能指被作品描绘的真实人物。后续只把精确的角色类型作为更窄的人工复核信号，仍不自动等同于“非真人”。

`Married To` 的 8 条人物对事实组成 4 组双向关系，样例包括 Archie Andrews 等虚构人物以及 Elizabeth I—Marilyn Monroe 的明显错误配对，维持排除决定；`Parent` 仅 2 条人物对，维持排除决定。

`freebase-links.txt` 前八行显示 `:d:<数字>:<名称>\tfreebase-entity\t<http://rdf.freebase.com/ns/m....>\t.`；后续完整扫描发现大多数行的主体是**普通名称**，因此前八行不能代表全文件格式。身份联结需要同时识别普通名称与 `:d:` 前缀名称，并统计名称到 MID 的覆盖及歧义，不能简单把同名视为同一实体。身份审计完成后，才评估能否构建带稳定标识的关系表。

### 2026-09-28：人物对子集的结构审计

### 2026-09-28：MID 审计解析错误与修正

第一次身份审计扫完 `freebase-links.txt` 的 42,539,895 行，报告 42,539,886 行为“意外主体格式”，全部 988,927 个目标名称都无 MID。**这些覆盖结果无效。** 原因是脚本把开头少量 `:d:` 前缀行误当成了全文件格式，跳过了绝大多数普通名称主体。脚本现已改为兼容两种主体格式，并增报各自的行数；必须运行修正版、写入新的输出目录后，才能解释 MID 覆盖率。

MID 对本项目是身份核验和跨库人物重合审计的重要依据；在 Freebase Easy 内部做暂时的关系语义与结构探索时，名称键已足够，不必把“有 MID”作为先筛人物的硬门槛。即使名称只对应一个 MID，也不能自动证明扁平化 `facts.txt` 的同名事实没有混合实体；同名多 MID 必须单独报告。

### 2026-09-28：身份审计第二次格式修正

修正主体名称解析后，完整扫描显示链接文件共 42,539,895 行，其中 42,539,886 行是普通名称主体，9 行是 `:d:` 前缀主体；全部可解析，无格式错误。人物对子集的 988,927 个不同名称中，脚本最初识别 948,371 个与 `m.` 形式的 ID 对应，但仍有 5,654 条目标链接 URI 形如 `<http://rdf.freebase.com/ns/g/11bbmqpbzw>`。脚本当时只接受 `m.`/`g.`，漏掉了 `g/`，故其“40,556 个名称无 MID、0 个名称多 MID”仍**不是最终结论**。现已兼容 `m.`、`g.`、`m/`、`g/` 四种后缀，并在摘要中按格式分别计数；需用新输出目录重跑核对。即使修正后一个名称仅有一条链接，也不能反推出源知识库绝无同名实体。

### 2026-09-28：MID 格式核对完成

修正版完整扫描同一链接文件，988,927 个目标名称中有 954,013 个匹配到一个可识别 Freebase ID（948,371 个 `m.`、5,642 个 `g/`，约 96.5%）；34,914 个没有可识别 ID，名称对应多个可识别 ID 的计数为零。另有 12 条目标链接指向 `people/american_indian_group`、`visual_art/artwork` 等类型 URI，不应当成实体 MID；这也再次说明 Person 候选与名字匹配子集存在类型污染。这里“零多 MID”只指当前链接文件的映射结果，不足以证明 `facts.txt` 的同名事实没有被扁平化合并。下一步只用人物对子集和这份名称状态表统计**逐关系边的 ID 覆盖**，不以无 MID 为由删边；确定属性抽取需求后再安排一次合并式全量事实扫描。

`scripts/freebase_easy_join_relation_mids.py` 只读取 `relation_candidates_v1.tsv` 和 `name_mid_status.tsv`，给每条候选记录附两端的链接文件 ID 状态，分别统计两端都有唯一 ID、仅一端有、两端都无、至少一端有歧义的数量，并标出不同名称落到同一 ID 的自指边。输出保留所有原始候选记录；任何缺 ID 情况都先作为审计标记，不能在这一步隐式删边或宣称链接文件 ID 已精确解析 `facts.txt` 的实体身份。

## 5. 每个新数据源的决策记录模板

在启动训练前填写以下问题并保存答案：

| 问题 | 必须提供的证据 |
| --- | --- |
| 这个来源收录的是哪些人？ | 来源说明、人物判定规则、原始人物数与最终人物数 |
| 哪些边真能表示人物间关系？ | 谓词频次、逐类样例、两端人物核查、方向与中介说明 |
| 职业标签能否与现有任务比较？ | 原始值分布、映射表、未映射率、每类有效人数 |
| 能否做历史时期分析？ | 生卒/事件年份覆盖率、按时期的有效样本及缺失率 |
| 与既有来源独立到什么程度？ | 实体或页面重合、共同上游来源、可能的选择偏差 |
| 哪种泛化主张成立？ | 各库内复现、匹配样本复现或跨库迁移的明确实验设计 |

若上述任一核心项尚无证据，状态写“待审计”，不把下载完成或模型可运行当作数据有效。决策可以是“进入建图”“只作描述性对照”或“暂不使用”，并附理由。后续所有数据集都沿用这份记录格式。
