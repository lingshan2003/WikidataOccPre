## 筛选规则

1. 从 `BIOG_MAIN` 读取人物 ID、姓名和**原始**生卒年。每个人至少有一个非 0 的生年或卒年；公元前负年份保留。排除 3 个五位数出生年和 5 个出生晚于死亡的人，不用索引年、活动年代补缺。
2. 每人只有一个单层职业。只要 `POSTED_TO_OFFICE_DATA` 有官职记录，职业记为“做官”；否则按白名单从 `STATUS_DATA` 选清楚的宽泛职业。无职业候选、只有非职业身份码，或出现多个不同的非官职业类别的人不进入表。官位高低、L1/L2/L3 均不参与。
3. 从 `KIN_DATA` 与 `ASSOC_DATA` 收集所有关系类别。亲属关系的原始码与中文名、交往关系的原始码与官方一级类别都保留。交往表中带亲属中介或第三人物的 8,959 行，不能安全地解释为 `c_personid → c_assoc_id` 直接关系，因此不写成二人三元组；其余记录要求两端 ID 不同且关系码有效。
4. 两端人物都必须满足第 1、2 条。对同一来源、同一原始关系码、同一方向的人物对合并重复记录，`SupportRows` 保存合并前行数。原库中互为反向的关系记录仍保留各自方向。

`Relation` 是可追溯的原始码（如 `KIN:75`、`ASSOC:22`）；`RelationLabelZh` 是码表中的中文名称。`RelationGroup` 提供较粗的来源/一级类别：亲属暂记 `kinship`，交往记官方一级码 `association_01` 至 `association_10`，未映射的已知码记 `association_unclassified`。**原始码只用于溯源，不表示模型一定使用数百种关系类型。** 本表先固定两端人物的资格和原始三元组，亲属关系最终如何归并可在此基础上决定，无须重跑人物筛选。

人物字段分别带 `Node1_`、`Node2_` 前缀：姓名、生年、卒年、职业及职业来源。缺少的生年或卒年留空；每个人至少有其中一个年份。

## 筛选结果

| 阶段 | 数量 |
| --- | ---: |
| `BIOG_MAIN` 全部人物 | 661,712 |
| 至少有一个可用生卒年的人 | 93,688 |
| 同时有明确单层职业的人 | 38,789 |
| 符合条件的原始亲属行 | 26,802 |
| 符合条件的原始直接交往行 | 71,755 |
| 去重后的有向、带原始类型三元组 | **92,168** |
| 三元组涉及不同人物 | **22,392** |

完整三元组中，亲属为 26,802 条，交往为 65,366 条（去重后），共保留 630 个实际出现的原始关系码供溯源。交往中著述一级类别 `association_05` 占 53,045 条。三元组涉及的人物有 21,504 人标为“做官”，占 **96.0%**；92,168 条边中 87,071 条两端都是“做官”，占 **94.5%**。因此这张表满足当前筛选条件，但若直接拿来做多职业预测，类别分布会严重偏向“做官”。这是原始资料与两端职业、年份筛选共同产生的限制。

已验证输出没有重复的有向原始类型三元组、没有缺职业或缺两种生卒年的端点；随机抽查 124 行与 SQLite 原始关系和人物年份一致，`SupportRows` 总和为 98,557。
