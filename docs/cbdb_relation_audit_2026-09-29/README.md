# CBDB 关系类型初探（2026-09-14 SQLite 版）

## 范围与口径

直接读取 `external_data/cbdb/2026.09.14/cbdb_20260914.sqlite3` 的 `KIN_DATA`、`ASSOC_DATA` 及官方码表。下列计数都是**原始数据库行数**；尚未去除反向镜像、重复人物对、自环或间接关系，也未按主实验的关系语义白名单筛选。完整的已出现编码见 [亲属码表](kinship_codes.tsv)、[交往码表](association_codes.tsv) 和 [交往子类](association_subtypes.tsv)。运行 `python3 scripts/cbdb_relation_inventory.py` 可重新导出这些表。

## 粒度说明

这里列出的亲属和交往细码仅用于了解原始数据。重新建图时采用适度的关系粒度，不直接把数百个细码作为模型关系类型；具体归并规则另行确定。

| 数据表 | 原始行 | 已出现的关系码 | 官方码表中的关系码 | 说明 |
| --- | ---: | ---: | ---: | --- |
| `KIN_DATA` | 562,367 | 438 | 488 | 人物到人物的亲属称谓，含辈分、长幼、姻亲及远亲等细分 |
| `ASSOC_DATA` | 190,044 | 484 | 498 | 人物交往/行为的细分编码，官方还定义了一级、二级类别 |
| 合计 | 752,411 | 922（分属两套码表） | 986 | 亲属原始行占 74.74% |

**编码数不是互相独立的社会关系数。** 如 `父` 与 `子`、`为 Y 之学生` 与 `学生为 Y` 是方向相反的表述。按码表所给的反向码及倒置人物 ID 查找，190,044 条交往行中 189,897 条（99.92%）有对应反向三元组；562,367 条亲属行中 535,125 条（95.16%）能用两个候选反向码中的一个找到倒置三元组。此检查只验证镜像是否存在，未核对来源、时间、文字等上下文，因此不能据此直接除以二得到事件数。

## 亲属关系长什么样

`KINSHIP_CODES` 提供中文称谓、亲属路径（如 `F` 父、`S` 子）、简化路径、两个可能的反向码，以及上行、下行、婚姻和旁系步数。高频编码如下：

| 原始码 | 称谓 | 行数 |
| ---: | --- | ---: |
| 75 | 父 | 92,108 |
| 180 | 子 | 91,810 |
| 126 / 125 | 弟 / 兄 | 57,188 / 57,164 |
| 134 / 135 | 丈夫 / 妻子 | 29,706 / 25,694 |
| 62 / 243 | 祖父 / 孫 | 29,124 / 28,549 |
| 111 | 母 | 18,927 |

这套编码还区分长子、次子、继子、嫡母、姻亲和多代祖先/后裔。原始细码保存在清单中，供解释和质量检查。

## 交往关系长什么样

`ASSOC_CODES` 记录具体行为与反向码；`ASSOC_CODE_TYPE_REL` 把编码接到 `ASSOC_TYPES` 的 10 个一级家族、35 个二级子类。以下是官方一级家族的原始行数，占比分母为 `ASSOC_DATA` 的 190,044 行。

| 一级家族 | 行数 | 占交往行 | 已出现的细码 |
| --- | ---: | ---: | ---: |
| 著述关系 | 138,320 | 72.78% | 155 |
| 学术关系 | 20,639 | 10.86% | 80 |
| 政治关系 | 17,246 | 9.07% | 120 |
| 朋友关系 | 8,572 | 4.51% | 10 |
| 社会关系（笼统） | 2,349 | 1.24% | 37 |
| 军事关系 | 1,572 | 0.83% | 15 |
| 财务关系 | 375 | 0.20% | 14 |
| 宗教关系 | 238 | 0.13% | 4 |
| 家庭关系 | 188 | 0.10% | 16 |
| 医疗关系 | 26 | 0.01% | 4 |
| **未映射到官方类别** | **519** | **0.27%** | **29** |

另有 22 行只映射到一级码 `01`，没有二级子类；因此二级子类表的行数合计是 189,503，而已映射一级家族的行数合计是 189,525。

著述关系的主要二级子类是应酬文字 33,513 行、书札文字 29,915 行、墓志文字 23,561 行、序跋文字 23,545 行。具体细码的高频例子：`贈詩、文` 11,887 行与其反向码 `收到 Y 的贈詩、文` 11,885 行；`致書 Y` 9,755 行与反向码 9,753 行；`為 Y 作墓誌銘` 8,811 行与反向码 8,809 行。其他有 `友` 7,341 行、`為 Y 之學生` 4,275 行与反向码 4,272 行、`推薦` 1,542 行与反向码 1,542 行。

因此，“非亲属”绝大多数是**有具体行为含义的著述记录**，不能一概解释为朋友或长期社会联系。墓志、传记等文字关系也不等同于两人生前直接交往。学术类含师生、共同研究主题和学术攻讦；政治类含支持、荐举、上下级与对抗；相同一级家族内也存在明显不同的方向和语义。

## 建图前需要处理的结构问题

1. **官方分类未覆盖全部实际编码。** 29 个已出现的交往码、519 行没有 `ASSOC_CODE_TYPE_REL` 映射，例如 `為 Y 的墓誌銘書丹`（128 行）、`墓誌銘由 Y 書丹`（125 行）、`與 Y 為講學`（65 行）。这些行不应静默丢弃或猜测归类。
2. **并非每行都能无条件视为直接人物对。** `ASSOC_DATA` 还有来源/对象的亲属码与亲属 ID 等字段；两侧这四个字段均为零的有 181,095 / 190,044 行，其余至少有一侧带亲属指向信息。另有 22 行填写了第三人物 ID。仅按 `c_personid → c_assoc_id` 扁平化时，需核对这类记录的语义。
3. **存在少量端点异常。** 亲属表有 61 行、交往表有 327 行满足任一端人物 ID 非正或两端相同；具体建图需分别记录剔除原因。
4. **一级类型仍不均衡。** 原始交往行的 72.78% 属著述家族，医疗、宗教、家庭交往、财务关系均很稀疏。比较模型结果时需留意不同一级类型的样本量。

关系粒度不在本报告中冻结；本报告的所有数字均来自原始 CBDB 表。
