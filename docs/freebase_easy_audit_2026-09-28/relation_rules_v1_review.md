# Freebase Easy v1 人物关系规则草案

状态：**待审阅**。本文件只确定关系谓词的含义与处理规则；职业保持原始 `Profession` 值，不构建 L1/L2/L3。输入证据是本目录的 `review_samples.json`、`pair_subset_audit_report.txt` 和 `关系谓词初审.md`。所有计数都是名称匹配的候选事实，尚不是真实人物关系数。

## 目标与边界

- v1 保留原始 `source_line`、主体名、谓词、客体名；后续附加链接文件中的 ID 和状态，不用名称匹配或有 ID 直接证明身份。
- 关系图先包含含义明确的亲属、伴侣和人物影响等**有类型**的边；师承、任职等关系在源字段方向和图的语义范围核实后扩展。不同类型不合并成无类型的“认识”。
- 不按职业或日期是否存在筛除关系边。缺失信息留到节点与标签阶段报告。
- 下面的“保留”表示进入下一轮子集核验，不表示已通过逐条实体真实性审核。

## 对下一轮子集核验的要求

1. 只读取已导出的 `relation_candidates_v1.tsv` 或带 ID 的版本，**不重新扫描完整 `facts.txt`**；输入、输出均须写明版本与路径。
2. 逐谓词报告原始记录数、双向去重数、自环数、缺失 ID 数、规范化后唯一边数；按 `source_line` 保留审计轨迹。
3. 把同一对人物跨谓词的重叠与互相矛盾关系单列；不因另一个谓词出现就自动删边。
4. 对 `Children` 的双向、同名自环和亲子/兄弟姐妹重叠抽样复核；对影响关系检查互逆映射是否正确。
5. 报告“通过已定义结构与 ID 条件的边”和“保留来源但仍有疑点的边”两套计数。链接 ID 只能提供身份线索，不能单独证明每条 Easy 事实的两端确实是对应的人物；不能把候选数当最终图规模。

这张规则表先保留为待审阅草案。按新的探索顺序，先运行 `scripts/freebase_easy_filter_person_cohort.py`，用已有 `person_attributes.tsv` 筛出有原始职业且有可解析出生年或死亡年的人物候选名称，再从**全部 163 个有名称匹配人物对的谓词**中观察该子集的关系分布。此举只缩小审计范围，不证明这些记录就是人物关系；随后再结合本表审定关系语义。
